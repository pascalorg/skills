# Worked example: a textured crate scene

> **This fixture is synthetic.** It is generated by
> `scripts/make-fixture.mjs`, not exported from a real modelling tool. It was
> built to contain one target for every pass in the skill, so the numbers below
> are honest measurements of a *deliberately bad* file. A real Blender or
> photogrammetry export will not shrink by 99%. Use this to learn the shape of
> the workflow and the trade-offs, not as a promise of a ratio.

Every number on this page came from the two scripts in `scripts/`, run on
2026-09-11 with `@gltf-transform/cli@4.5.0`, KTX-Software 4.4.2, Node v26.7.0 on
macOS 15 arm64.

## Reproducing it

```bash
bash <skill-path>/scripts/make-fixture.sh before.glb
# Installing dependencies...
# wrote before.glb — 29297696 bytes
```

The generator is deterministic: on the versions above it writes a file that is
byte-identical to the 29,297,696-byte `before.glb` measured here (verified with
`cmp`).

## What is wrong with the input

`scripts/glb-audit.sh before.glb` and `gltf-transform inspect` between them show:

- **Two byte-identical 2048×2048 PNG albedo maps** (12,722,911 B each), plus an unreferenced 1024×1024 PNG (3,182,216 B) — 28.6 MB of the 29.3 MB file is images
- **4 materials, one unreferenced** (`Unused_Glass`, `BLEND`), one an exact duplicate (`Crate_dup`)
- **Non-indexed geometry** — 3 primitives, 20,808 vertices, no index buffers; 6,936 unique triangles drawn as 7,056
- **13 nodes with meshes**, 12 of them reusing 2 crate meshes
- **A two-node empty helper chain** (`Helper_Empty` → `Helper_Empty_child`)
- **48 MiB of texture VRAM** at load, from 4 B/texel RGBA8 plus mipmaps
- Spec-clean: `validate` reports no errors and no warnings, only 3 INFO entries (`NODE_EMPTY /nodes/15`, `UNUSED_OBJECT /images/2`, `UNUSED_OBJECT /materials/3`)

The scene is 4.4 × 1 × 3.2 m, +Y up, which is a plausible real-world size. That
number is the one to defend through every pass.

## The run

The name-preserving pipeline from `SKILL.md`, step by step, with the real size
after each command:

| Step | Command | Output bytes |
|---|---|---|
| input | — | 29,297,696 |
| 1 | `dedup before.glb s1.glb` | 16,572,684 |
| 2 | `prune s1.glb s2.glb` | 13,390,152 |
| 3 | `weld s2.glb s3.glb` | 12,882,476 |
| 4 | `resize s3.glb s4.glb --width 1024 --height 1024` | 2,083,212 |
| 5 | `etc1s s4.glb s5.glb --quality 128` | 310,356 |
| 6 | `meshopt s5.glb after.glb --level high` | **186,528** |

Where the wins came from: `dedup` collapsed the two identical textures (−12.7 MB),
`prune` dropped the unused texture and material (−3.2 MB), `resize` to 1024 px was
the single biggest lever (−10.8 MB, a 4× texel reduction no codec can recover),
`etc1s` took the remaining image to a block-compressed KTX2 (−1.77 MB), and
`meshopt` compressed the geometry (−124 KB). `weld` only saved 508 KB of bytes but
cut vertices 20,772 → 3,601 and added `u16` index buffers, which is what the GPU
cares about (`inspect` on `s2.glb` vs `s3.glb`).

| Transfer (gzip -9) | 24,558,816 B | 160,150 B | −99.3% |
| Transfer (brotli -q 11) | 10,104,870 B | 158,874 B | −98.4% |
| Texture VRAM (est.) | 48.00 MiB | 0.67 MiB | −98.6% |
| Draw calls | 13 | 13 | 0 |
| Triangles | 7,056 | 7,056 | 0 |
| Textures | 3 | 1 | −2 |
| Materials | 4 | 1 | −3 |
| World size | 4.4 × 1 × 3.2 m | 4.4 × 1 × 3.2 m | unchanged |
| Animations | 0 | 0 | 0 |
| Load time | not measured (no browser run) | | |

**Changed:** deduped 2 byte-identical 2048px textures, 1 duplicate material and
1 duplicate mesh; pruned 1 unused texture, 1 unused material and 2 empty helper
nodes; welded non-indexed → indexed (20,772 → 3,601 vertices); resized 2048 →
1024; encoded KTX2/ETC1S at quality 128; meshopt-compressed geometry.

**Verified:** world size unchanged at 4.4 × 1 × 3.2 m; all 14 app-visible node
names kept (`Assembly`, `Shell`, `Crate_00`…`Crate_11`); triangle count identical;
0 animations before and after; `validate` reports no errors.

**Not verified:** load time — nothing was rendered in a browser. The audit
script's numbers are file-level, not runtime.

**Regression the script flagged, and why it was accepted:**

```
"namedNodesLost": ["Helper_Empty", "Helper_Empty_child"],
"regressions": ["2 named node(s) removed or renamed"]
```

`prune` drops empty leaf nodes. In this fixture nothing resolves those names, so
it is fine. **In a real asset, check the app first** — if it looks up an
attachment point or camera target by name, run `prune --keep-leaves` and the
count stays at 16.

**Requires:** `EXT_meshopt_compression`, `KHR_mesh_quantization`,
`KHR_texture_basisu`. The target loader needs `MeshoptDecoder` and `KTX2Loader`
wired up — see `references/loader-support.md`.

## Validator false positive on KTX2

`gltf-transform validate after.glb` reports one WARNING and one extra INFO that
are **not** real problems:

```
WARNING  IMAGE_UNRECOGNIZED_FORMAT  Image format not recognized.  /images/0
INFO     UNSUPPORTED_EXTENSION      ... 'EXT_meshopt_compression'  /extensionsUsed/0
INFO     UNSUPPORTED_EXTENSION      ... 'KHR_texture_basisu'       /extensionsUsed/2
INFO     UNUSED_OBJECT              This object may be unused.     /images/0
```

The bundled Khronos validator (`gltf-validator@2.0.0-dev.3.10`) cannot parse a
KTX2 payload or resolve a `KHR_texture_basisu` reference, so it calls the image
unrecognized and possibly unused. Verified by comparing against the WebP variant
of the same pipeline, which validates with no errors and **no warnings**. Treat
`IMAGE_UNRECOGNIZED_FORMAT` on a KTX2 image as expected; do not "fix" it.

## Routes not taken, measured

Same input, other pipelines, all audited with the same script:

| Output | Bytes | Brotli | VRAM MiB | Draws | Tris | Named nodes | `Crate_00` kept | Requires |
|---|---|---|---|---|---|---|---|---|
| **KTX2 + meshopt** (the run above) | 186,528 | 158,874 | 0.67 | 13 | 7,056 | 14 | yes | meshopt + quantization + basisu |
| `optimize` with structure passes off | 274,352 | 246,525 | 0.67 | 13 | 7,056 | 14 | yes | meshopt + quantization + basisu |
| `optimize` with defaults | 276,288 | 252,118 | 0.67 | 2 | **6,740** | **1** | **no** | meshopt + quantization + basisu |
| WebP + meshopt (no KTX2 needed) | 375,668 | 348,653 | **5.33** | 13 | 7,056 | 14 | yes | meshopt + webp + quantization |
| WebP + `instance` + meshopt | 375,252 | 348,703 | 5.33 | **2** | 7,056 | **2** | **no** | meshopt + webp + quantization |
| WebP + `instance` + Draco | 358,564 | **354,917** | 5.33 | 2 | **6,987** | 2 | **no** | webp + draco |
| `gltfpack -cc -tc -tl 1024 -kn -km` | 640,312 | 411,530 | 2.00 | 13 | 7,056 | **16** | yes | meshopt + quantization + basisu |

What that table settles on this fixture:

- **KTX2 beats WebP on VRAM by 8×** (0.67 vs 5.33 MiB) at the same 1024px source, because WebP is decoded to RGBA8 on the GPU and ETC1S is not. On a texture-heavy asset that matters more than the file size.
- **Draco is smaller raw but bigger over the wire.** 358,564 B vs meshopt's 375,252 B raw, yet 354,917 B vs 348,653 B after brotli — meshopt output is designed to be re-compressed. Draco also changed the triangle count (7,056 → 6,987; its quantization collapses degenerate triangles) and decodes more slowly.
- **`instance` cut draw calls 13 → 2 and erased 12 node names.** A real win if nothing resolves crates by name, a broken app if something does.
- **`optimize` with defaults is destructive**: 1 named node left and 316 triangles gone, for 1,936 bytes *more* than the same command with `--simplify false --join false --flatten false --instance false --palette false`. The safe variant is the better default.
- **`gltfpack -kn -km` was the only route that kept all 16 names**, including the empty helpers, but produced the largest output here because it does not resize as aggressively and keeps all three textures.

## Commands that did nothing, and why

Worth knowing so you do not report a phantom win:

- `gltf-transform jpeg in.glb out.glb` on a PNG-textured file left the image data unchanged (1,923,641 B in and out) — the `jpeg` command's `--formats` defaults to `jpeg`, so it only touches existing JPEGs. `--formats png` produced 413,156 B.
- `gltf-transform join` made the file **bigger**: 12,882,440 → 12,890,228 B. The scene reuses two crate meshes across 12 nodes, so joining duplicated shared vertices. `--keepNamed` left the size unchanged because every node is named.
